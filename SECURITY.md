# Security policy

## Supported versions

See [SUPPORT.md](SUPPORT.md). Before the first release, there are no released versions. Once published, only versions listed as supported there are eligible for security fixes.

## Reporting a vulnerability

Please report suspected vulnerabilities privately through [GitHub's private vulnerability reporting form](https://github.com/rakrsh/dash-file-uploader/security/advisories/new). Do not report security issues in public issues, discussions, or pull requests. If the private reporting form is unavailable or disabled, contact the maintainer through the contact method on [@rakrsh's GitHub profile](https://github.com/rakrsh). The maintainer must enable private vulnerability reporting in repository settings before the first public release.

Include the affected version or commit, impact, reproduction steps, and any relevant logs or proof of concept. Avoid including real user files, credentials, or personal data.

The maintainer aims to acknowledge reports within five business days, provide an initial assessment within ten business days, and share an update at least every 30 days while a report remains open. These are response goals, not a guaranteed service level.

## Coordinated disclosure

Please allow the maintainer a reasonable opportunity to investigate, prepare a fix, and coordinate an advisory before public disclosure. The maintainer will work with the reporter on a disclosure timeline and provide attribution if desired. Do not access, modify, or retain data that is not yours while investigating.
